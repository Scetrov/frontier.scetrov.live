v0 [`Character`](https://github.com/evefrontier/world-contracts/blob/6fd08169ba4c0e880e91548cd0314cbb91bc92ed/contracts/world/sources/character/character.move) is a dedicated deterministic shared object carrying tenant identity, tribe, wallet, metadata, and owner-cap identity. v1 uses a generic [`Entity`](https://github.com/evefrontier/world-contracts/blob/acb0a16cd4b754bd9c41c058007932f131a7f258/contracts/core/sources/entity.move) with an installable [`Identity`](https://github.com/evefrontier/world-contracts/blob/acb0a16cd4b754bd9c41c058007932f131a7f258/contracts/character/sources/identity.move) component. Installing identity emits `CharacterCreated` with character ID, key, tribe ID, and address; the layout and event schema differ from v0. The same component now supports an admin-gated tribe-ID edit and emits `CharacterUpdated` only on change.

v0 combines `GovernorCap`, sponsor-aware `AdminACL`, and typed `OwnerCap`; see [`access_control`](https://github.com/evefrontier/world-contracts/blob/6fd08169ba4c0e880e91548cd0314cbb91bc92ed/contracts/world/sources/access/access_control.move). v1 represents authorization as requirements consumed while completing an Entity request and uses [`AccessCap`](https://github.com/evefrontier/world-contracts/blob/acb0a16cd4b754bd9c41c058007932f131a7f258/contracts/core/sources/services/access_cap.move). An Entity stores the ID of its minted cap; a caller cap records the authorized entity for downstream routing, not ownership of an action target.

Location is a security-significant difference. v0 validates server identity, sender, target hash, signature, and deadline using [`location`](https://github.com/evefrontier/world-contracts/blob/6fd08169ba4c0e880e91548cd0314cbb91bc92ed/contracts/world/sources/primitives/location.move). Active v1 has a reusable server-signed proof verifier:
[`proof`](https://github.com/evefrontier/world-contracts/blob/acb0a16cd4b754bd9c41c058007932f131a7f258/contracts/core/sources/services/proof.move) checks kind, sender, deadline, and that the server is an admin, then [`sig_verify`](https://github.com/evefrontier/world-contracts/blob/acb0a16cd4b754bd9c41c058007932f131a7f258/contracts/core/sources/services/sig_verify.move) verifies the server's Ed25519 personal-message signature. Docking itself now records a relationship on both [Entity](https://github.com/evefrontier/world-contracts/blob/acb0a16cd4b754bd9c41c058007932f131a7f258/contracts/core/sources/entity.move) objects through two admin-gated requests. The docking operation does not invoke the reusable proof verifier.
This describes a source-level trust-boundary difference, not a runtime or security-quality verdict.
